# Ultra Hook

Use the smallest workflow that can establish the requested outcome. Inspect the
applicable repository instructions and available tools, identify the acceptance
evidence, and handle a bounded change directly when coordination adds little value.
Keep the user's leader model and persistent configuration unchanged.

## Establish the task

Extract the outcome, affected surface and constraints from the request and current
repository state. State a concrete completion check before substantial edits, such
as the failing CLI invocation succeeding or a particular UI assertion passing.
Resolve answerable technical uncertainty by inspecting or running a bounded experiment;
ask only for missing product choices, access or authority that the evidence cannot supply.
Continue independent authorized work while a required answer is pending.

Choose the useful entry below; these are decision aids, not mandatory phases:

| Request | First useful action | Completion evidence |
| --- | --- | --- |
| Fix a defect | Reproduce the trigger or isolate a falsifiable hypothesis | Original failure checked after the fix plus relevant regressions |
| Add behavior | Settle the observable contract, data ownership and failure cases | Acceptance checks through the changed interface |
| Refactor | Identify the behavior callers depend on | That behavior remains intact; review the affected diff |
| Review | Establish scope and read the diff with its callers | Findings tied to a location, trigger and consequence |
| Optimize | Establish workload, baseline and correctness constraint | Comparable measurements and preserved correctness |
| Research | Identify answerable questions and suitable primary sources | Conclusions traced to evidence with uncertainty stated |

A read-only investigation or review stays read-only unless implementation is already
authorized. A missing reproduction is an evidence gap, not permission to invent one.
Do not turn a bounded task into an open-ended optimization loop.

## Load only what the task needs

Load only the reference needed for the current decision:

- Before delegating or escalating, read [teams and models](references/teams-and-models.md).
  It defines live-catalog selection, continuing dialogue, ownership and escalation.
- For architecture, debugging, code review or measured optimization, consult the
  relevant section of [engineering](references/engineering.md).
- For a research assignment, read [research](references/research.md).
- For UI behavior or visual changes, use our [AgentController integration skill](../agentcontroller/SKILL.md)
  for [Kasempiternal's external tool](https://github.com/Kasempiternal/agentcontroller)
  ([upstream downloads](https://github.com/Kasempiternal/agentcontroller/releases)).
  Other checks can supplement its evidence; they do not replace required UI validation.

Use native collaboration only when authorized by the request or applicable
instructions. An orchestration request can justify a bounded team; a keyword or
available slot alone does not. No fixed agent count, banner, prompt-rewriting phase
or mandatory chain of reviewers is part of this workflow.

The lead remains responsible for decisions, integration, verification and the final
answer. Discuss actionable findings with workers while work is underway, and reuse
their context for follow-up. Explain the resulting behavior, the evidence actually
obtained and any unresolved limitations. Retain only useful decisions and unfinished
handoffs; saved files do not authorize restarting a task.

For a resumed task, compare the handoff with current files, diff and relevant checks.
Reuse credible evidence for unchanged inputs; rerun when changes, failures or missing
evidence make it necessary. Record the next unresolved action and its owner for a
long task, without saving private transcripts or unrelated profile data.

Close with what changed, what was actually verified and what remains unresolved.
Distinguish implemented, tested and published: one does not imply the others. Publish
only within existing authorization; completing local work creates none.

This skill adds no authority for external communication, publication, deployment,
credential access or unrelated changes. Routing advice and hook checks do not create
a sandbox, enforce a spending limit or prove a quality improvement.
